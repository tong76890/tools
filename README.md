# 个人工具箱

本仓库用于上传、保存和维护我自己编写的工具，集中保留各工具的源码、文档及打包后的可执行程序，方便后续使用、修改和归档。命令行托盘工具是本工具箱收录的第一个工具，后续工具也按独立目录收录。

## 文档分工

- 根目录 `README.md`：介绍整个工具箱，维护工具索引，并规定适用于所有工具的全局规则。
- 各工具目录中的 `README.md`：介绍该工具的功能、使用方法、构建与打包方式，以及该工具特有的说明。
- 各工具的其他文档：放在所属工具目录内，由该工具的 README 提供入口。

## 统一目录结构

以下结构是所有工具必须遵守的仓库标准。已有工具不符合时须按此整改，新增工具直接按此创建。

```text
仓库根目录/
├── README.md               # 工具箱介绍、工具索引和全局规则
├── <工具名称>/
│   ├── README.md           # 工具入口说明
│   ├── src/                # 源码及编译所需的资源文件
│   ├── docs/               # 规格、设计、使用说明等详细文档
│   ├── tests/              # 测试代码、脚本和数据
│   │   ├── src/            # 测试源码
│   │   ├── scripts/        # 测试执行、验证脚本
│   │   └── data/           # 测试输入、样例及预期结果等文件
│   ├── scripts/            # 构建、打包等工程辅助脚本
│   ├── dist/               # 编译成品及运行配套文件
│   ├── build/              # 本地构建中间文件和临时输出，不纳入版本管理
│   └── …                   # 构建配置等工程文件
└── <其他工具名称>/         # 遵守相同结构
```

源码、文档和编译成品必须分开存放，不得自行更换上述目录名称或将内容散放在工具根目录。

- `src/`：保存源码、头文件及编译所需的图标、资源等文件；可按模块继续划分子目录。
- `docs/`：保存除入口 `README.md` 外的工具文档，例如 `docs/SPEC.md`，由工具 README 提供链接。
- `tests/`：集中保存测试内容，测试代码放在 `tests/src/`，测试脚本放在 `tests/scripts/`，测试输入、样例及预期结果等文件放在 `tests/data/`。测试代码不得混入正式源码目录；测试生成的临时文件放在 `build/tests/`，不纳入版本管理。
- `scripts/`：保存构建、打包等工程辅助脚本；测试脚本统一放在 `tests/scripts/`，不与工程辅助脚本混放。
- `dist/`：统一保存编译、打包后供直接使用的可执行程序，以及运行所需的配置、资源和依赖文件，并纳入版本管理。需要保留多个版本或平台时，在 `dist/` 内继续分目录。
- `build/`：仅用于本地构建，不作为成品归档位置；构建完成后，将需要保存的可运行成品整理到 `dist/`。

各工具根目录的构建配置和辅助脚本应使用上述路径；各工具 README 统一说明从 `dist/` 获取程序、从 `src/` 查看源码、从 `docs/` 查阅详细文档，并说明测试执行方法。目录按实际内容创建，无对应内容时无需提交空目录；已有内容必须放在规定位置。

## 全局规则

1. **每个工具独立存放。** 每个工具在仓库根目录下拥有自己的目录，源码、文档、资源和打包后的可执行程序均归入该目录。
2. **每个工具都有独立 README。** 至少说明用途、运行环境、使用方法、源码位置、构建或打包步骤，以及打包程序的存放位置。
3. **同时保留源码、文档和可执行程序。** 可执行程序应附带运行所需的配置、资源或依赖说明，让使用者能找到可运行版本，也能根据源码重新构建。
4. **统一目录布局。** 所有工具必须使用 `src/` 存放正式源码、`docs/` 存放详细文档、`tests/` 存放测试代码、脚本和数据、`scripts/` 存放工程辅助脚本、`dist/` 存放编译成品及运行配套文件；工具根目录保留入口 README、构建配置等工程文件。不得为不同工具另设一套存放位置。
5. **更新时保持内容对应。** 修改工具后，同步更新相关文档；更新打包程序时说明其版本或对应源码，避免使用说明、源码和可执行程序不一致。
6. **新增工具时更新索引。** 在根 README 的工具列表中补充工具名称、简要功能和独立 README 链接。工具专属细节放在各自目录中，全局约定统一维护在本文件。
7. **按目标平台选择工程方式。** Windows 专用工具优先使用 Visual Studio 工程（如 `.sln`、`.vcxproj`）组织源码和编译，工程文件保留在工具根目录，源码仍统一放在 `src/`。跨平台工具可以考虑使用 CMake 组织构建。无论采用哪种方式，均须遵守上述目录标准，并在工具 README 中说明所需开发环境、构建和打包步骤。
